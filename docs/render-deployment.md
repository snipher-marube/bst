# Deploying to Render

AnalyticsMeta ships with a `render.yaml` Blueprint that auto-configures the web service on Render.

---

## Prerequisites

- A Render account at [render.com](https://render.com)
- A PostgreSQL database already created in Render (Dashboard → New → PostgreSQL)
- An Upstash Redis database at [upstash.com](https://upstash.com) (free tier is enough to start)
- Your code pushed to a GitHub repository

---

## 1. Trigger the Blueprint deploy

1. Go to Render Dashboard → **New → Blueprint**
2. Connect your GitHub repository
3. Render auto-detects `render.yaml` and shows the services to create
4. Click **Apply**

This creates one **web service** (Daphne ASGI). The Celery worker and beat services are commented out in `render.yaml` until you need them (they require a paid Starter plan).

---

## 2. Set environment variables

After the Blueprint runs, go to your **web service → Environment** tab and fill in every `sync: false` variable:

### PostgreSQL (from Render Dashboard → your DB → Connection)

| Variable | Where to find it |
|---|---|
| `PG_DATABASE_NAME` | Database field |
| `PG_DATABASE_USER` | Username field |
| `PG_DATABASE_PASSWORD` | Password field |
| `PG_DATABASE_HOST` | Hostname field |
| `PG_DATABASE_PORT` | `5432` |

### Upstash Redis (from Upstash Console → your DB → Details)

| Variable | Value |
|---|---|
| `REDIS_URL` | Full `rediss://:password@host:6380` URL |
| `REDIS_HOST` | Hostname only (e.g. `us1-xxx.upstash.io`) |
| `REDIS_PORT` | `6380` (Upstash TLS port) |

### Django / Security

| Variable | Value |
|---|---|
| `SECRET_KEY` | Auto-generated by Render (`generateValue: true`) |
| `ALLOWED_HOSTS` | `your-app.onrender.com` (add custom domain after setup) |
| `SITE_URL` | `https://your-app.onrender.com` |
| `ADMIN_NAME` | Your name |
| `ADMIN_EMAIL` | Your email — receives Django error reports |

### Email (Gmail SMTP)

| Variable | Value |
|---|---|
| `EMAIL_HOST_USER` | your-email@gmail.com |
| `EMAIL_HOST_PASSWORD` | Gmail App Password (not your login password) |

### OAuth

| Variable | Value |
|---|---|
| `GOOGLE_CLIENT_ID` | From Google Cloud Console |
| `GOOGLE_CLIENT_SECRET` | From Google Cloud Console |
| `LINKEDIN_CLIENT_ID` | From LinkedIn Developer Portal |
| `LINKEDIN_CLIENT_SECRET` | From LinkedIn Developer Portal |

For OAuth redirect URI configuration see [oauth-setup.md](oauth-setup.md).

### M-Pesa

| Variable | Value |
|---|---|
| `MPESA_CONSUMER_KEY` | From Safaricom Developer Portal |
| `MPESA_CONSUMER_SECRET` | From Safaricom Developer Portal |
| `MPESA_SHORTCODE` | Your M-Pesa paybill/till number |
| `MPESA_PASSKEY` | From Safaricom portal |
| `MPESA_CALLBACK_URL` | `https://your-app.onrender.com/subscriptions/mpesa/callback/` |

## 3. First deploy

Render runs this sequence automatically on every deploy:

```
1. pip install -r requirements.txt
2. python manage.py collectstatic --noinput   (build step)
3. python manage.py migrate                   (preDeployCommand)
4. daphne -b 0.0.0.0 -p $PORT config.asgi:application
```

---

## 4. Create the superuser

After the first successful deploy, open the Render **Shell** tab for your web service and run:

```bash
python manage.py createsuperuser
```

---

## 5. Add a custom domain (optional)

1. Render Dashboard → your service → **Settings → Custom Domains**
2. Add your domain and follow the DNS instructions
3. Update `ALLOWED_HOSTS` to include the new domain (comma-separated):
   ```
   ALLOWED_HOSTS=your-app.onrender.com,yourdomain.com
   ```
4. Update `SITE_URL` and `MPESA_CALLBACK_URL` to use the new domain

---

## 6. Enable Celery workers (paid plan)

When you're ready to pay for background workers ($7/month each), uncomment the two worker blocks in `render.yaml` and push to GitHub. Render will create the services automatically.

The workers need the same environment variables as the web service. Use **Copy from service** in the Render dashboard to avoid re-entering them.

---

## Useful Render shell commands

```bash
# Run Django management commands
python manage.py shell
python manage.py showmigrations
python manage.py dbshell

# Check Celery (when workers are enabled)
celery -A config inspect ping
celery -A config inspect active
```

## Free tier limitations

| Resource | Render Free |
|---|---|
| Web service | Spins down after 15 min inactivity — first request takes ~30s |
| Postgres | 1 GB storage, shared CPU |
| Celery workers | Not available on free tier |
| Custom domains | Supported |
| HTTPS | Automatic |

To keep the free web service warm, set up an external uptime monitor (e.g. [UptimeRobot](https://uptimerobot.com)) to ping `/health/` every 10 minutes.
